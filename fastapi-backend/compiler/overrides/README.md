# Local PTITCube compatibility fixes

Base: PTITCube/PTITCube-Library main, commit `b684dc01a76d4a0f5e646339cefa9cad2672c85b` (2026-11-26, EPS getters return 0 when the gauge is unread; previously `74065b6`, `57cf1c3` v1.1.0). The two upstream commits after `74065b6` only touch `src/EPS/EPS.cpp`, which is not overridden.
This is the same library every PTITCube Lab repository vendors in `lib/PTITCube` at that date.
`prepare.py` overlays these files onto the installed library's `src/` before compiling trusted dependencies. They are not edits to submitted sketches or changes published upstream.

Library layout since 74065b6: `CDH/` (CDH, Scheduler, Storage, WDT), `MUX/` (MUX, Camera, GPS), `COM/`, `EPS/`, `Sensor/`. Every override file replaces the upstream file at the same path; nothing may be added under the old `Camera/`, `GPS/`, `Scheduler/` or `Storage/` directories, which would duplicate classes.

Upstream adopted earlier platform patches, so they are no longer overridden: the CDH console type for ESP32-S3 (`PTIT_ConsoleSerial`), the bounded WiFi/config-portal timeouts, native MPU6500 support and the 8 g / 500 °/s ranges.

- `MUX/MUX.cpp`: one shared `Serial2` instance; switching changes the baud with `updateBaudRate` instead of re-running `begin()` on every switch. Break-Before-Make kept.
- `MUX/Camera.h`, `MUX/Camera.cpp`: capture command `p` (accepted by PTITCube ESP32_CAM_Firmware, which also takes `capture`/`photo`, and by `app/firmware/camera-slave`). Validates `SIZE` (4..524288), stops on `ERROR:`, writes a `.part` file and renames it only for a complete JPEG (byte count, SD write count, SOI/EOI), always sends `DONE`, feeds a registered task watchdog during long transfers and always hands UART2 back to GPS. Without a MUX (pins 255) UART2 stays at the camera baud; upstream left it at 9600 so direct-wired captures timed out. `isReady()` still means SD readiness, not a working image sensor.
- `MUX/GPS.cpp`: `hasFix()` also requires a fix younger than 5 seconds; a directly wired GPS gets its 9600 baud.
- `CDH/Scheduler.h`: `PTIT_BUS_UART2` (4) and `PTIT_BUS_MQTT` (5) get their own mutexes. Upstream aliases UART2 to the console mutex, so a camera transfer blocked every Serial print.
- `CDH/Scheduler.cpp`: bus mutexes are recursive, created race-free. The library itself locks I2C in `Sensor::update()` and SPI in `logData()`; a task that already holds that bus (Lab7-02 does) otherwise waits out the timeout and then uses the bus without the lock. Recursive mutexes do not make arbitrary task code thread-safe.
- `CDH/Storage.cpp`: writes report success only when every byte was written. This also fixes `touch` (writing "" returned 0 = failure upstream).
- `CDH/CDH.cpp` (upstream copy) + `CDH/PTITCloud.h`, `CDH/PTITCloud.cpp` (platform addition, not upstream): `cdh.begin()` answers the web app's provisioning handshake over Serial (`[CLOUD] CFG? v1 uid=… host=<host>:<port> ssid=…` / `@PTITCLOUD {json}`; the web app answers KEEP only for the same account device, WiFi and broker), keeps WiFi + MQTT settings in NVS and starts a low-priority task that publishes every new JPEG under `/photos` to `sensors/<uid>/image`. Students write no upload code. `cdh.read()/available()/peek()` consume `@PTITCLOUD` lines and pass every other line through unchanged. Photos already on the card at boot are not re-sent; a photo is sent once its size is stable across two scans and it has JPEG SOI/EOI. WiFi is started only if the sketch has not started WiFi itself, and never while the sketch runs an access point. TLS currently uses `setInsecure()` (HiveMQ demo).
- `Sensor/Sensor.h`, `Sensor/Sensor.cpp`: readings are NaN while a sensor is absent or its last read failed (upstream keeps stale values), MPU register reads end with STOP instead of a repeated start, at most 50 Hz sampling (also bounds the re-detection probes). Upstream re-detection, the I2C bus lock and units are kept: Celsius, hPa, m/s², rad/s and **microtesla** (upstream 74065b6 changed the magnetometer from Gauss to µT).

The build configuration revision must change whenever these patches change so an outdated compiler image cannot return an accepted artifact. Current revision: v9. Rebuild from `fastapi-backend` with `docker build --provenance=false -f compiler/Dockerfile -t pscubesat-compiler:1 .` (`setup-local` does this on every install; without provenance an unchanged rebuild keeps the same image ID, which `catalog.json` records).

Hardware verification and limits: `Docs/CURRICULUM_SERIAL_AUDIT_2026-10-15.md` at repository root. Sensor wiring currently uses ESP32 GPIO21/22; do not infer S3 pin compatibility from compilation alone. Corrected curriculum sketches are in `app/firmware/curriculum/` and must be selected explicitly; the compiler never silently rewrites user source.
